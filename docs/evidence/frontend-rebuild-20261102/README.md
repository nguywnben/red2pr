## Login focus and recovery-link interaction correction — 2026-11-02

- **Scope:** Corrected the two reported interactions on `/login`; this is a targeted follow-up, not completion of the 21-screen rebuild. The branch remains `main`, based on HEAD `4dfde2f9140af5e6b87b79b07e987ab6ae77c292`. All changes remain uncommitted in the pre-existing dirty worktree.
- **Versioned references:** `@astryxdesign/core@0.7.4` and `@astryxdesign/theme-neutral@0.7.4` are the installed/locked versions. Read the installed Astryx CLI docs with `pnpm exec astryx component TextInput`, `pnpm exec astryx component Link`, `pnpm exec astryx docs tokens/tokens-focus`, and `pnpm exec astryx docs theme --dense` from `apps/web`. The focus reference defines a 2px solid ring with a 3px offset and theme focus tokens. The official [Astryx releases](https://github.com/meta/astryx/releases) and [API conventions](https://github.com/meta/astryx/wiki/API-Conventions) were also checked.
- **Computed-style diagnosis:** The Neutral TextInput is composed of an inner native input and an Astryx rounded wrapper. Core sets the inner input outline to `none`; its shared input wrapper owns the focus border and inset token shadow. The app's old unlayered `:focus-visible` selector in `src/shared/theme/tokens.css` overrode Astryx's layered component CSS, adding a second hard-coded `#0052cc` outline. In headless Edge, clicking both text inputs matched `:focus-visible`, which made that custom selector visible even on pointer interaction.
- **Recovery-link diagnosis:** Login placed the Astryx Link directly inside a stretch-aligned `VStack`, so the link's box expanded from its text width to the card width. Astryx's `:active` state applies the `--color-overlay-pressed` token to the link element, producing the wide bar. `:hover` only underlined the link; pointer focus did not match `:focus-visible`; keyboard Tab applied Astryx's 2px ring with 3px offset. Text selection was a separate browser selection state (`Selection.toString()` returned the selected phrase, and the screenshot shows only the selected glyph range).
- **Fix:** Removed the app-wide focus selector and its hard-coded light/dark focus tokens, leaving Astryx components to render their own focus states and browser-native controls to retain browser behavior. Wrapped only the recovery link in a zero-gap `HStack`, letting it remain content-sized. Did not add a global `outline: none` or suppress focus styles. Added the missing thin Astryx export boundary in `src/shared/ui/AstryxComponents.ts`, routed the auth pages through `src/shared/ui`, and kept the generated theme imports under `src/shared/theme` to satisfy the existing FE-05 import boundary. Removed one unused test import found by the requested lint gate. Shared-source search found one Repositories link incorrectly borrowing the removed focus token for its text color; that obsolete inline color override was removed so Astryx supplies the link color.
- **Headless browser verification:** `node docs/evidence/frontend-rebuild-20261102/focus-state-check.cjs final` — exit `0`, headless Microsoft Edge via Playwright Core 1.56.1, loopback-only Vite at `127.0.0.1:5182`, 1440×960. Assertions cover both TextInputs under pointer and Tab in light/dark, recovery hover/active/pointer-focus/keyboard-focus/blur, selection, the absence of the legacy token, and page errors. Both input wrappers showed one visible 2px inset Astryx focus treatment; each link press overlay was constrained to its 215.3px text-sized link box; the keyboard link ring was `2px solid` with `3px` offset. There were no browser page errors.
